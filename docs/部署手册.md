# 部署手册（前端）

面向第一次部署、不打算改代码的人。全程约 20 分钟，**都在 Cloudflare 网页完成**，不需要装 Node.js，也不需要克隆仓库。

> 本工程是**纯前端**（Vue 3 页面），必须先部署后端 `cloudflare-myblog-api`。
> 前后端部署在**同一个域名**下，前端页面才能正常调用接口。

---

## 0. 先做一件事：部署后端

前端所有请求都写的是相对路径（`/api/admin/blogs`、`/api/app/blogs/query` 等），
**没有配置任何后端地址**。因此必须让 `/api/*` 和页面处在同一个域名下。

如果还没部署后端，先看 **cloudflare-myblog-api** 的部署手册，按里面的步骤建好：

- D1 数据库 `db_myblog`（含表结构）
- Worker（粘贴 `dist/index.js`）
- 记下这个 Worker 的名字，第 5 步要用

> 后端没部署时，前端页面能打开，但登录和列表都会报错 —— 这是正常的，不是前端的问题。

---

## 1. 开始前确认

| 需要 | 说明 | 是否必须 |
| --- | --- | --- |
| **Cloudflare 账号** | 免费版即可 | ✅ 必须 |
| **已部署的后端 Worker** | 接口来源，见上一节 | ✅ 必须 |
| **一个域名** | 已托管到 Cloudflare，页面与接口都挂在这个域名下 | ✅ 必须（见下方说明） |
| **Pages 项目** | Cloudflare 的静态托管，账号自带，创建项目时自动启用 | ✅ 必须（默认已有） |

> **为什么必须有域名**：前端请求是相对路径 `/api/*`，需要把该路径路由到后端 Worker。
> Cloudflare 的 Workers 路由只能挂在**自己的域名**上，`*.pages.dev` 这类平台子域不支持配置路由。
> 所以「页面 + 接口」跑在同一个自定义域名下是这套方案的硬性前提。

---

## 2. 准备页面文件

**不需要在本地构建**。可以直接用仓库里已经构建好的产物：

1. 打开仓库页面，进入 `dist` 目录
2. 下载整个 `dist` 文件夹（GitHub 上可以点 **Code → Download ZIP** 下载仓库后取其中的 `dist`）
3. 解压后确认里面**直接**就是这些内容：

```
dist/
├── index.html          ← 必须在这一层，不能多套一层 dist/dist
├── admin/
│   ├── index.html
│   ├── blogs/index.html
│   ├── blogClass/index.html
│   ├── database/index.html
│   ├── link/index.html
│   ├── notepad/index.html
│   ├── systemconfig/index.html
│   ├── user/index.html
│   └── welcome/index.html
├── app/
│   ├── index.html
│   ├── blog/index.html
│   ├── blogs/index.html
│   └── welcome/index.html
├── login/index.html
├── assets/
├── library/
├── web.loader*.js      ← 页面加载器，必须一起上传
└── favicon*.ico
```

以上共 15 个页面入口（根目录 1 个 + admin 9 个 + app 4 个 + login 1 个）。
上传时**照原样传整个文件夹**，不要只挑 `index.html` 或改动目录层级。

> **多页结构，别改层级**。本工程是**多页构建**，每个页面都有自己的 `index.html`。
> 上传时保持目录原样即可，不需要额外配置单页回退规则。

---

## 3. 创建 Pages 项目

1. Cloudflare 面板 → **Workers 和 Pages**
2. **创建** → **Pages** → **使用直接上传**（Upload assets）
3. 项目名称填 **`pages-myblog`**（可自定义，后面绑域名用得到）
4. 把第 2 步准备好的 `dist` 文件夹**拖进去**（或选择该文件夹）
5. 点 **部署站点**

部署完成后，Cloudflare 会给一个 `xxx.pages.dev` 地址。
现在打开它应该能看到页面**渲染出来**，但登录会失败 —— 因为接口还没接通。

---

## 4. 绑定自定义域名

1. **Workers 和 Pages** → `pages-myblog` → **自定义域**
2. **设置自定义域** → 输入你的域名，例如 `blog.example.com`
3. 按提示完成 DNS 绑定（域名已托管在 Cloudflare 时通常一步完成）

绑定后访问 `https://blog.example.com`，应能看到页面。

---

## 5. 把 `/api/*` 路由到后端 Worker（关键一步）

这一步不做，页面能打开但所有数据都是空的、登录会失败。

1. 进入域名：Cloudflare 面板 → 选中你的域名（`example.com`）
2. 左侧菜单 **Workers 路由** → **添加路由**
3. 填写：

| 字段 | 填写内容 |
| --- | --- |
| 路由 | `blog.example.com/api/*` |
| Worker | 选择第 0 步部署的后端，例如 `cloudflare-myblog-api` |

4. 保存

> 路由是 `blog.example.com/api/*`，**注意域名要和前端绑定的域名完全一致**。
> 保存后访问 `https://blog.example.com/api/test?uuid=hello` 应返回 JSON，
> 说明前后端已经连通。

---

## 6. 验证

按顺序访问（把域名换成你自己的）：

### ① 页面能打开

```
https://blog.example.com
```

### ② 接口连通

```
https://blog.example.com/api/test?uuid=hello
```

应返回：

```json
{"status":200,"message":"Hello from test!","uuid":"hello"}
```

### ③ 数据库连通

```
https://blog.example.com/api/app/blogClass
```

返回分类列表（空数组 `[]` 也算成功，说明后端连上了 D1）。

### ④ 登录

打开 `https://blog.example.com/login`，用后端部署时创建的账号登录：

```
用户名：admin
密码：  admin
```

> 这是后端初始化时写入的默认账号，**首次登录后请立刻改密码**。

登录成功后会跳转到后台首页 `https://blog.example.com/admin/welcome`，能看到统计图表即为部署完成。

几个常用入口：

| 地址 | 页面 |
| --- | --- |
| `https://blog.example.com/` | 前台，自动跳到 `/app` |
| `https://blog.example.com/app/blogs` | 前台文章列表 |
| `https://blog.example.com/login` | 登录 |
| `https://blog.example.com/admin/welcome` | 后台首页 |

---

## 7. 更新前端

**部署者**：重新下载仓库最新的 `dist` 文件夹，在 Pages 项目里重新上传并点部署即可。
域名与路由配置不用再动。

**维护者**：改完代码后本地构建，再提交产物：

```bash
bun install          # 首次
bun run build        # 产出 dist/
```

构建完成后再提交 `dist/` 目录。

## 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 页面能开，但列表全空、登录失败 | `/api/*` 没路由到后端 Worker | 重新检查第 5 步 |
| 访问 `/api/test` 返回 404 | 路由写错，或域名不一致 | 核对路由里的域名与前端域名是否相同 |
| 打开子页面 404 | 上传时多套了一层目录，`index.html` 没在根层 | 确认上传的是 `dist` **里面的内容** |
| 登录成功但刷新又退出 | 前后端不同域导致 Cookie 不发送 | 确认后端绑定的是同一个域名；见下方说明 |
| 页面样式/图标丢失 | `assets/`、`library/` 没一起上传 | 整个 `dist` 一起上传，不要只传 `index.html` |
| 显示的是旧页面 | Pages 有缓存，或没点部署 | 用无痕窗口验证；确认已点 **部署** |

### 关于登录态

后端登录成功后会写入 `HttpOnly` Cookie。浏览器只在**同域**下才会自动携带该 Cookie。

因此：

- ✅ 页面 `blog.example.com` + 接口 `blog.example.com/api/*` —— 正常
- ❌ 页面 `xxx.pages.dev` + 接口 `blog.example.com/api/*` —— **登录会失败**

这就是第 4、5 步必须绑定同一个自定义域名的原因。如果暂时只想先看页面效果，可以先不登录。

## 附：本地开发（可选，与部署无关）

只部署的话，这一节可以跳过。

```bash
bun install
bun run dev        # http://localhost:5173
```

### 接口地址由 `vite.config.ts` 的 `server.proxy` 决定

`/api` 请求会被转发到 **`proxy.target`** 配置的地址。仓库当前默认指向线上：

```ts
proxy: {
  '/api': {
    target: 'https://blog.myhome.top',   // ← 当前配置
    changeOrigin: true
  }
}
```

两种用法：

| 场景 | 做法 |
| --- | --- |
| **只想看页面效果** | 保持默认。前端连线上接口，**不需要本地启动后端** |
| **要联调本地后端** | 把 `target` 改成本地地址，例如 `http://127.0.0.1:8787`，同时启动后端 |

联调本地后端时需要**两个终端**：

| 终端 | 命令 | 地址 |
| --- | --- | --- |
| 后端 | `bun run dev`（在 cloudflare-myblog-api 目录） | `http://127.0.0.1:8787` |
| 前端 | `bun run dev`（在本工程目录） | `http://localhost:5173` |

> ⚠️ 修改 `proxy.target` 属于本地调试配置，**注意不要把它和业务改动一起提交**，
> 否则会影响其他人拉取后的开发环境。

**环境要求**：Node.js 18+（推荐 20/22 LTS）与 Bun。
